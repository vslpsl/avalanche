## Purpose

Генерирует Prometheus rule groups (recording rules и alerting rules),
соответствующие текущей конфигурации генерации метрик avalanche, чтобы
можно было воспроизвести на целевом Prometheus нагрузку от rule
evaluation engine, а не только от scrape/remote-write. Дополнительно
делает генерацию значений серий воспроизводимой через явный seed.

## ADDED Requirements

### Requirement: Флаг seed для воспроизводимой генерации значений
Система ДОЛЖНА (SHALL) предоставлять флаг `--seed` (int64, по умолчанию
`0`). При `--seed=0` генератор значений ДОЛЖЕН (SHALL) использовать
источник на основе текущего времени, как и раньше. При ненулевом
`--seed` генератор значений ДОЛЖЕН (SHALL) быть инициализирован этим
значением, так что последовательность генерируемых значений серий
одинакова между запусками с одинаковым конфигом.

#### Scenario: Одинаковый seed даёт одинаковые значения
- **WHEN** avalanche запущен дважды с одинаковым конфигом и одинаковым
  `--seed=42`
- **THEN** последовательности значений (Set/Add/Observe) серий совпадают
  между двумя запусками

#### Scenario: Seed по умолчанию не меняет прежнее поведение
- **WHEN** avalanche запущен без `--seed` (значение по умолчанию `0`)
- **THEN** генератор значений использует источник на основе времени, как
  до этого изменения

### Requirement: Стабильность имён метрик и ключей labels
Имена метрик и ключи labels (например, `label_key_<...>_<idx>`) ДОЛЖНЫ
(SHALL) полностью выводиться из конфигурации запуска (счётчики типов
метрик, `--label-count`, `--metricname-length`, `--labelname-length`,
`--const-label`) и оставаться неизменными на протяжении жизни процесса,
за исключением явного переименования через `--metric-interval`. Значения
`series_id` и `cycle_id` НЕ ДОЛЖНЫ (SHALL NOT) считаться частью этого
контракта стабильности — они могут меняться в результате churn'а серий.

#### Scenario: Одинаковый конфиг даёт одинаковый набор имён и ключей labels
- **WHEN** avalanche запускается дважды с идентичным конфигом
- **THEN** множество имён метрик и множество ключей labels (без учёта
  `series_id`/`cycle_id`) идентично между запусками

### Requirement: Флаг пути для вывода файла правил
Система ДОЛЖНА (SHALL) предоставлять флаг `--rules-output-path` (строка,
по умолчанию пустая). Если флаг пуст, генерация файла правил ДОЛЖНА
(SHALL) быть отключена и поведение avalanche НЕ ДОЛЖНО (SHALL NOT)
меняться относительно текущего. Если флаг задан, avalanche ДОЛЖЕН (SHALL)
записать по этому пути файл в формате Prometheus rule groups
(`groups: [...]`) один раз при старте, до начала обслуживания `/metrics`.

#### Scenario: Флаг не задан — поведение без изменений
- **WHEN** avalanche запущен без `--rules-output-path`
- **THEN** файл правил не создаётся, побочных эффектов на файловую
  систему нет

#### Scenario: Флаг задан — файл создаётся при старте
- **WHEN** avalanche запущен с `--rules-output-path=/tmp/avalanche-rules.yml`
- **THEN** до начала обслуживания `/metrics` по указанному пути
  создаётся валидный YAML-файл в формате Prometheus rule groups

### Requirement: Recording rules по сгенерированным метрикам
Система ДОЛЖНА (SHALL) предоставлять флаг `--recording-rule-count` (целое
число, по умолчанию `0`), задающий число recording rules для генерации.
Каждое сгенерированное recording rule ДОЛЖНО (SHALL) ссылаться на имя
одной из сгенерированных метрик и использовать выражение, соответствующее
её типу (например, `sum by (<label>) (...)` для gauge/counter с `rate()`
для counter, `histogram_quantile(...)` для histogram/native histogram).

#### Scenario: Recording rules не генерируются по умолчанию
- **WHEN** avalanche запущен без `--recording-rule-count` (по умолчанию
  `0`)
- **THEN** файл правил (если включён) не содержит recording rules

#### Scenario: Recording rules соответствуют типу метрики
- **WHEN** `--recording-rule-count=10` и среди сгенерированных метрик
  есть classic histogram
- **THEN** хотя бы одно recording rule для этой метрики использует
  `histogram_quantile` над `rate(<metric>_bucket[...])`

### Requirement: Alerting rules по сгенерированным метрикам
Система ДОЛЖНА (SHALL) предоставлять флаг `--alerting-rule-count` (целое
число, по умолчанию `0`), задающий число alerting rules для генерации.
Каждое сгенерированное alerting rule ДОЛЖНО (SHALL) содержать `alert`,
`expr` (пороговое условие над сгенерированной метрикой или recording
rule), `for` и непустые `labels`/`annotations`.

#### Scenario: Alerting rules не генерируются по умолчанию
- **WHEN** avalanche запущен без `--alerting-rule-count` (по умолчанию
  `0`)
- **THEN** файл правил (если включён) не содержит alerting rules

#### Scenario: Alerting rule содержит обязательные поля
- **WHEN** `--alerting-rule-count=5`
- **THEN** каждое сгенерированное alerting rule содержит непустые
  `alert`, `expr`, `for`, `labels`, `annotations`

### Requirement: Группировка и интервал вычисления правил
Система ДОЛЖНА (SHALL) предоставлять флаги `--rule-group-size` (целое
число, по умолчанию `10`) и `--rule-eval-interval` (секунды, по умолчанию
`60`). Сгенерированные rules ДОЛЖНЫ (SHALL) быть распределены по группам
не более чем по `rule-group-size` правил в каждой, и каждая группа ДОЛЖНА
(SHALL) иметь `interval`, равный `--rule-eval-interval`.

#### Scenario: Правила распределены по группам заданного размера
- **WHEN** `--recording-rule-count=25`, `--rule-group-size=10`
- **THEN** сгенерировано 3 группы с 10, 10 и 5 правилами соответственно

### Requirement: Файл правил не обновляется автоматически после старта
Файл, записанный по `--rules-output-path`, СОЗДАЁТСЯ (SHALL) один раз при
старте и НЕ ДОЛЖЕН (SHALL NOT) переписываться автоматически при
последующих изменениях состояния (churn серий, смена значений). Если
активен `--metric-interval` (переименование метрик), система НЕ ДОЛЖНА
(SHALL NOT) гарантировать, что ранее записанный файл правил продолжает
ссылаться на существующие имена метрик после переименования.

#### Scenario: Файл не меняется в течение работы процесса
- **WHEN** avalanche работает с `--rules-output-path` и активным churn'ом
  серий (`--series-interval`/`--partial-series-churn-percent`)
- **THEN** содержимое файла правил на диске не меняется после
  первоначальной записи при старте
