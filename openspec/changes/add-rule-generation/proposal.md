## Why

Основную нагрузку на Prometheus-совместимую систему часто создают не сами
серии, а вычисление recording и alerting rules над ними. Сейчас avalanche
умеет генерировать только сырые серии (scrape/remote-write), но не создаёт
нагрузку через rule evaluation engine и не даёт способа применить готовый
набор правил на целевом Prometheus, который соответствовал бы реально
сгенерированным метрикам. Кроме того, значения серий сейчас не
воспроизводимы между запусками (seed = `time.Now().UnixNano()`), что
затрудняет детерминированное тестирование alerting rules (например,
проверку, что конкретный alert предсказуемо сработает).

## What Changes

- Добавляется флаг `--seed` (int64, по умолчанию `0` = использовать
  время как раньше; ненулевое значение делает генерацию значений серий
  воспроизводимой между запусками при одинаковом конфиге).
- Формально фиксируется контракт: имена метрик и ключи labels (но не
  значения `series_id`/`cycle_id`) полностью выводятся из конфигурации
  запуска и стабильны в рамках жизни процесса (за исключением явного
  churn имени метрики через `--metric-interval`, который остаётся вне
  этого контракта).
- Добавляется генерация Prometheus rule groups (recording rules и
  alerting rules), встроенная в сам avalanche: при старте, если задан
  `--rules-output-path`, avalanche пишет на диск YAML-файл с группами
  правил, соответствующими текущей конфигурации генерации метрик
  (по именам метрик и стабильным ключам labels).
- Новые флаги для управления объёмом и формой генерируемых правил:
  `--rules-output-path`, `--recording-rule-count`,
  `--alerting-rule-count`, `--rule-group-size`, `--rule-eval-interval`.
- Файл правил пишется один раз при старте и не обновляется автоматически
  при последующем churn'е (значения `series_id`/`cycle_id` не влияют на
  правила: правила ссылаются только на имя метрики и ключи labels, а не
  конкретные значения, поэтому остаются валидными при обычном churn
  серий; но переименование метрики через `--metric-interval` файл правил
  не отслеживает — вне рамок этого изменения).
- Функциональность полностью опциональна: при `--rules-output-path=""`
  (по умолчанию) поведение avalanche не меняется.

## Capabilities

### New Capabilities
- `rule-generation`: генерирует файл Prometheus rule groups (recording +
  alerting), соответствующий текущей конфигурации генерации метрик, и
  делает генерацию значений серий воспроизводимой через `--seed`.

### Modified Capabilities
(нет)

## Impact

- Код: `metricsgen/serve.go` (детерминированный `valGen`, доступ к
  списку сгенерированных метрик/labels), новый файл
  `metricsgen/rulesgen.go` (генерация YAML rule groups), `cmd/avalanche/avalanche.go`
  (проброс новых флагов, запись файла при старте).
- Файловая система: при заданном `--rules-output-path` avalanche пишет
  файл на диск — новый побочный эффект, которого не было раньше (нужно
  явно включать флагом).
- Зависимость: используется формат Prometheus rule groups
  (`groups: [...]`), совместимый с `rule_files:` в конфиге целевого
  Prometheus — пользователь сам подключает сгенерированный файл в
  `rule_files:` и делает reload/restart целевого Prometheus (avalanche
  этого не делает).
- Нет изменений в существующих флагах генерации метрик или в
  wire-формате scrape/remote-write.
