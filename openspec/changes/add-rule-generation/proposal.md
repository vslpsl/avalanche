## Why

Основную нагрузку на Prometheus-совместимую систему часто создают не сами
серии, а вычисление recording и alerting rules над ними. Сейчас avalanche
умеет генерировать только сырые серии (scrape/remote-write), но не создаёт
нагрузку через rule evaluation engine и не даёт способа применить готовый
набор правил на целевом Prometheus, который соответствовал бы реально
сгенерированным метрикам. Кроме того, значения серий сейчас не
воспроизводимы между запусками (seed = `time.Now().UnixNano()`), что
затрудняет детерминированное тестирование alerting rules (например,
проверку, что конкретный alert предсказуемо сработает).

## What Changes

- Добавляется флаг `--seed` (int64, по умолчанию `0` = использовать
  время как раньше; ненулевое значение делает генерацию значений серий
  воспроизводимой между запусками при одинаковом конфиге).
- Формально фиксируется контракт: имена метрик и ключи labels (но не
  значения `series_id`/`cycle_id`) полностью выводятся из конфигурации
  запуска и стабильны в рамках жизни процесса (за исключением явного
  churn имени метрики через `--metric-interval`, который остаётся вне
  этого контракта).
- Добавляется генерация Prometheus rule groups (recording rules и
  alerting rules), встроенная в сам avalanche и отдаваемая через новый
  HTTP-эндпоинт: если `--rules-endpoint-path` не пуст (по умолчанию
  `/rules` — включено из коробки), avalanche регистрирует на этом пути
  GET-хендлер, отдающий YAML с группами правил, соответствующими текущей
  конфигурации генерации метрик (по именам метрик и стабильным ключам
  labels). `--rules-endpoint-path=""` явно отключает эндпоинт.
- Новые флаги для управления объёмом и формой генерируемых правил:
  `--rules-endpoint-path` (по умолчанию `/rules`), `--recording-rule-count`,
  `--alerting-rule-count`, `--rule-group-size`, `--rule-eval-interval`.
- Содержимое эндпоинта строится один раз при старте (детерминированно
  из конфигурации) и кешируется в памяти — каждый запрос отдаёт один и
  тот же закешированный YAML-снапшот, без пересборки на каждый запрос.
  Снапшот не обновляется автоматически при последующем churn'е (значения
  `series_id`/`cycle_id` не влияют на правила: правила ссылаются только
  на имя метрики и ключи labels, а не конкретные значения, поэтому
  остаются валидными при обычном churn серий; но переименование метрики
  через `--metric-interval` эта версия не отслеживает — вне рамок этого
  изменения).
- Генерация правил зависит только от конфигурации генерации метрик
  (счётчики типов метрик, `--label-count`, `--const-label` и т.п.) и
  НЕ зависит от того, сколько реплик avalanche с идентичным конфигом
  развёрнуто в кластере (сценарий: несколько подов-scrape-target/
  remote-writer с одинаковым конфигом, различаемых внешним label'ом
  вроде `pod`, добавляемым Prometheus при scrape/relabeling, пишут в
  один целевой Prometheus). Правила при этом группируют/фильтруют
  только по собственным меткам avalanche (`label_key_*`), не по внешним
  меткам вроде `pod`/`instance`/`job` — поэтому корректно агрегируют
  данные независимо от числа таких реплик.
- При `--rules-endpoint-path` по умолчанию (`/rules`), но
  `--recording-rule-count=0` и `--alerting-rule-count=0` (оба по
  умолчанию), эндпоинт зарегистрирован и отдаёт валидный, но пустой
  `groups: []` — поведение генерации метрик/scrape/remote-write при этом
  не меняется.

## Capabilities

### New Capabilities
- `rule-generation`: отдаёт по HTTP-эндпоинту YAML с Prometheus rule
  groups (recording + alerting), соответствующий текущей конфигурации
  генерации метрик, и делает генерацию значений серий воспроизводимой
  через `--seed`.

### Modified Capabilities
(нет)

## Impact

- Код: `metricsgen/serve.go` (детерминированный `valGen`, доступ к
  списку сгенерированных метрик/labels), новый файл
  `metricsgen/rulesgen.go` (генерация YAML rule groups),
  `cmd/avalanche/avalanche.go` (проброс новых флагов, регистрация
  HTTP-хендлера с закешированным снапшотом до начала обслуживания
  запросов).
- HTTP: avalanche регистрирует новый GET-эндпоинт
  (`Content-Type: application/yaml`) на `--rules-endpoint-path`
  (по умолчанию `/rules`) — новая поверхность API, которой не было
  раньше; включена из коробки, отключается явным
  `--rules-endpoint-path=""`.
- Зависимость: используется формат Prometheus rule groups
  (`groups: [...]`), совместимый с `rule_files:` в конфиге целевого
  Prometheus — пользователь сам скачивает содержимое эндпоинта (или
  настраивает файловый `rule_files:` через внешний механизм синхронизации)
  и делает reload/restart целевого Prometheus (avalanche этого не
  делает).
- Нет изменений в существующих флагах генерации метрик или в
  wire-формате scrape/remote-write.
