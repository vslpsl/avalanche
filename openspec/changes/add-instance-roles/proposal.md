## Why

Один процесс avalanche сегодня всегда одновременно: отдаёт `/metrics`,
опционально шлёт remote-write (`--remote-url`) и опционально отдаёт
сгенерированные Prometheus-рулы (`--rules-endpoint-path`, из
`add-rule-generation` — уже реализовано). В реальном деплое (Kubernetes)
удобнее развести это по специализированным подам: несколько подов
только scrape-target, несколько только remote-writer, один под —
только генератор/раздатчик рулов (ruler). При этом все эти поды должны
уметь работать с **одним и тем же** общим конфигом (то же количество
метрик/серий/лейблов/рулов), отличаясь только тем, какую роль играет
конкретный под — а раздавать десятки CLI-флагов на каждый под в
Kubernetes неудобно.

## What Changes

- Добавляется один флаг `--role` (enum, default `""`):
  - `""` — не меняет текущее поведение: каждая подсистема работает как
    сейчас, гейтясь только своим собственным триггер-флагом
    (`--remote-url` для remote-write, `--rules-endpoint-path` для
    рулов), `/metrics` всегда включён.
  - `"scrape-target"` — работает ТОЛЬКО `/metrics` (+ `/health`);
    remote-write и генерация/раздача рулов не запускаются, даже если их
    триггер-флаги заданы в общем конфиге.
  - `"remote-writer"` — работает ТОЛЬКО remote-write (+ `/health`);
    требует `--remote-url`, иначе ошибка валидации при старте.
    `/metrics` не регистрируется, рулы не генерируются.
  - `"ruler"` — работает ТОЛЬКО раздача сгенерированных рулов на
    `--rules-endpoint-path` (+ `/health`); требует непустой
    `--rules-endpoint-path`, иначе ошибка валидации при старте.
    `Collector` серий не создаётся вовсе (генерация рулов — чистая
    функция конфига, живые серии не нужны).
  - `"querier"` пока не поддерживается — будет добавлен вместе с
    `add-query-load`.
- Каждый существующий и новый флаг дополнительно читается из
  соответствующей переменной окружения `AVALANCHE_<FLAG_NAME>` (через
  встроенный в `kingpin` `Application.DefaultEnvars()`), явный CLI-флаг
  всегда переопределяет env. Это и есть механизм "один общий конфиг на
  все под-роли": общий `ConfigMap` с `AVALANCHE_*`-переменными
  монтируется во все Deployment'ы через `envFrom`, а различается только
  `--role`/`AVALANCHE_ROLE` в каждом из них.

## Capabilities

### New Capabilities
- `instance-roles`: эксклюзивный флаг `--role`
  (scrape-target/remote-writer/ruler) поверх существующих триггер-флагов
  подсистем, плюс универсальная поддержка env-переменных
  (`AVALANCHE_<FLAG_NAME>`) для всех флагов, позволяющая раздавать один
  общий конфиг на специализированные по роли инстансы.

### Modified Capabilities
(нет)

## Impact

- Код: только `cmd/avalanche/avalanche.go` (флаг `--role`, его
  валидация, условное создание `Collector`/регистрация `/metrics`/
  запуск remote-write/генерация и раздача рулов; `kingpin.CommandLine.
  DefaultEnvars()` + `NoEnvar()` на встроенных `--help`/`--version`).
  `metricsgen`-пакет не меняется — `NewConfigFromFlags`/
  `NewWriteConfigFromFlags` продолжают регистрировать флаги через
  переданный `flagReg`, и автоматически получают envar благодаря тому,
  что все они регистрируются на одном и том же `kingpin.CommandLine`.
- Не меняет wire-формат scrape/remote-write/рулов.
- **Явно вне scope этого изменения** (может стать отдельным будущим
  изменением, если понадобится): шардирование генерации серий между
  несколькими репликами одной роли (`--shard-index`/`--shard-count`) и
  роль `querier` (ждёт `add-query-load`).
